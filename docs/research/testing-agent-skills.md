# Оценка навыков настройки тестирования

Дата: 2026-11-10. Это предложение по оценке, а не результаты проведённых испытаний. Локальный контракт: [test-conventions-gate](../../skills/test-conventions-gate/SKILL.md) автоматически вызывается при неопределённости перед постоянной проверкой поведения; [establish-testing](../../skills/establish-testing/SKILL.md) — явно вызываемый workflow в свежей сессии ([метаданные](../../skills/establish-testing/agents/openai.yaml)). Шаблоны передачи — подсказки для текста, не протокол с обязательными заголовками.

## Что измерять

Anthropic рекомендует отдельно оценивать точность срабатывания, выполнение инструкций, результат и сосуществование навыков; примеры должны включать положительные, отрицательные и пограничные запросы, а прогоны — используемые модели ([руководство по оценке skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)). Для этого репозитория:

| Сценарий | Ожидаемый результат и свидетельство |
| --- | --- |
| Постоянный тест, нет решения о runner, расположении или команде | Gate срабатывает; агент изучает источники проекта, объясняет конкретный пробел, не выбирает соглашение сам и готовит содержательную передачу. |
| Противоречат CI и инструкции; один случайный тест или пустой каталог | Gate срабатывает; объясняет конфликт или недостаточность свидетельств. Доступный runner сам по себе не соглашение. |
| Все необходимые соглашения определены | Gate, если уже вызван, изучает применимые инструкции и возвращается к работе без передачи; блокировка здесь — ложноположительное закрытие gate. |
| Одноразовый диагностический probe, который не останется в репозитории | Автовызов gate не ожидается; его срабатывание здесь — ложноположительный вызов. Проверить и устойчивость к слову «тест» в запросах без добавления проверок. |
| Пользователь задал только часть решений | Gate сохраняет их в передаче и называет остальные пробелы; не предполагает, что опрос больше не нужен. |
| Доступна интерактивная новая сессия | До запуска получить выбор дерева; передать начальное сообщение напрямую, обеспечить маршрут возврата, не создавать временный файл. Сверять также применимые правила хоста, включая возможное требование явного запроса новой T3-сессии. |
| Интерактивный запуск или возврат недоступен / завершился ошибкой | Для запуска — переносимая передача в системном временном каталоге; для недоступного возврата — попросить пользователя принести результат. Не заявлять об успешной доставке. |
| Ожидание передачи и TDD / не TDD | При TDD остановить всю реализацию; иначе допустима производственная работа без изменения тестовых решений. После возврата проверить наличие изменений и перечитать инструкции. |
| Явная передача в establish-testing | Проверить исследование репозитория, интервью по оставшимся решениям, единый итоговый дизайн и подтверждение **до** правок; после согласования — работающая инфраструктура, документация и проверка, без исходного теста и бессмысленного постоянного smoke-теста. |
| Нет явного запроса establish-testing | Самопроизвольное включение нарушает локальный контракт явного вызова; отдельно проверить совместное присутствие обоих навыков. |
| Нет подтверждения, запуск или проверка заблокированы | Нет правок до подтверждения, нет ложного сообщения о завершении; незавершённые решения не выдаются за готовую передачу. |

Различать три исхода: навык обнаружен/загружен; агент фактически соблюдал нужные действия; итоговое состояние корректно. Лексическое упоминание имени не доказывает ни вызов, ни соблюдение. Проверять след действий, диалог и файловый diff: детерминированные проверки подходят для запретных изменений и факта вызовов, смысл доказательств и качество интервью — по рубрике человеком или оценщиком, откалиброванным на человеческой разметке. Не требовать точных формулировок или заголовков handoff. Такая комбинация проверок результата и траектории согласуется с [исследованием Anthropic об agent evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents).

## Дизайн сравнения

Для каждого сценария подготовить маленький изолированный репозиторий с заданными инструкциями, CI и состоянием файлов, реалистичный запрос и заранее размеченные критерии. Сравнить одинаковые задачи и окружения: текущий навык против сохранённой предыдущей версии при изменении; при оценке ценности самого навыка — дополнительно без него. Не передавать путь к навыку в прогонах на **автовызов**; отдельно принудительно загрузить его для оценки исполнения. Зафиксировать доступные другие навыки и повторить ключевые случаи вместе с ними. Anthropic [skill-creator](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md) использует сравнение с прежней версией или вариантом без навыка и сочетает количественную оценку с просмотром результатов.

Предлагаемые слои:

```text
статическая проверка метаданных и ссылок
  → симуляция: изолированная задача + контролируемые ответы пользователя и инструментов
    → реальный T3: интерактивное дерево → запуск → возврат → проверка результата
```

Симуляция позволяет воспроизводить отказы, ответы и запрещённые операции; она проверяет поведение относительно модели хоста, но не доказывает реальный запуск, доставку или доступность дерева. Для реального T3 нужны отдельное разрешённое пользователем интерактивное испытание, безопасный временный проект и настоящий маршрут возврата; фиксировать версию T3, доступность инструментов, условия запуска и наблюдаемые события. Проверять оба выбора дерева, наличие незакоммиченных изменений, доставку и отказ. Если инструкции конкретного хоста запрещают запуск без отдельного запроса пользователя, правильный исход — соблюсти это ограничение и сообщить о невозможности, а не обходить его. Нельзя считать симулированный возврат доказательством реального. Спецификации инструментов конкретной установки следует проверить при проведении испытания: они могут измениться.

Повторять независимые прогоны с чистым состоянием, фиксируя модель, версию навыка, окружение, запрос, транскрипт, ошибки инфраструктуры, время и стоимость. Отдельно сообщать долю корректных срабатываний среди положительных случаев, ложных срабатываний среди отрицательных и выполнение каждого критерия поведения; показывать числители и знаменатели, разбивку по случаям и неопределённость, а не только среднее. Для надёжности важны успех с первой попытки и согласованность повторов, а не best-of-N: [pass@k и pass^k](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) измеряют разные вещи. Мало повторов и общий сбой среды не дают надёжной оценки вероятности; результаты на одной модели или в одном хосте не обобщаются автоматически.

Ограничения: без проверки реального хоста нельзя утверждать работоспособность передачи; симулированный пользователь может не отражать настоящий интервью-процесс; LLM-оценщик ошибается и нуждается в калибровке. Проверять и сам детектор срабатывания по сырым событиям: иначе ошибка наблюдения может выглядеть как ошибка навыка. Держать отдельные от настроечных отложенные сценарии, чтобы изменения формулировок не оптимизировались только под известные примеры. Здесь прогоны, тесты и зависимости не создавались.
