# Response formatting

Keep the main answer and any request for a decision in ordinary text. Put supporting explanations of instructions or limitations in a separate Markdown blockquote. State the source when it can be shared and explain how it affects the response or work. Distinguish an explicit requirement from your interpretation.

Put incidental asides in a separate Markdown blockquote when they are outside the user's main topic but useful to disclose, such as acknowledging an unrelated process mistake or noting a separate handoff thread. Keep information needed to answer the request, explain the outcome, or make a decision in ordinary text.

When a skill requires confirmation or approval, name and link the exact `SKILL.md`, quote the relevant instruction, and explain how it applies.

Follow higher-priority instructions and the user's explicit formatting preferences if they conflict. Do not create an approval requirement merely to use this format.
